# C5 模擬與評估框架

**目的**：提供**已知真相**的合成學生族群，讓每個部件在接觸真人前就能被量測（L3），並把每個盲區變成可重跑的情境（L4）。
**為什麼最優先**：C1、C2、C4 的 G2 關卡都卡在 C5。沒有 C5，只能靠直覺判斷演算法好不好。

## 子部件

| ID | 功能 | 內容 |
|---|---|---|
| C5.1 | 合成學生產生器 | 每位學生有：真實需求 $w^*$；熟悉集合 $F^*$（依學程知名度與學生背景抽樣）；**錨點選擇模型**＝契合度與名氣的混合（可調比例，用來重現 B-C1-2）；**作答模型**＝真實值 + 雜訊 + 社會期許偏誤 + 默許傾向 + 題序效應（可個別開關） |
| C5.2 | 指標庫 | 需求還原 RMSE、Kendall τ、Recall@k、「相關且不知道」比例、覆蓋率、熱門度 KL、Brier、區間涵蓋率；每個指標都有手算測試 |
| C5.3 | 消融執行器 | 一次只換一個子部件（例如 C2.1 v0→v1），其他固定；輸出指標差異與信賴區間 |
| C5.4 | 盲區情境 | 登錄表中每個 B 項目對應一個情境設定，例如「名校錨點比例 80%」「作答者只回答第一個選項」 |
| C5.5 | 第二套生成模型 | 與 C5.1 **不同家族**的生成模型：C5.1 是原型混合（潛在類別），C5.5 改用無原型的連續分布（例如 Dirichlet 或獨立 Beta），用來檢查 S-1 循環驗證 |

## 關鍵風險：循環驗證（S-1）
如果模擬器假設學生需求是連續向量、作答是「真值 + 高斯雜訊」，而 C1 也用同樣的模型估計，L3 一定會過，但沒有證明任何事。對策：
1. C5.5 第二套生成模型必須和估計器的假設不同；
2. 每個 L3 結果都要附上「在誤設情境下」的數字；
3. L3 結果只能用來**淘汰**明顯錯誤的設計，不能用來**證明**設計正確，那是 L5 的工作。
