# Validation plan

「學生沒想過的 program」沒有現成的標準答案，所以驗證分成三類：**演算法正確性**（可自動化）、**離線代理指標**（需歷史案例）、**使用者研究**（需真人）。

## A. 演算法正確性（自動化，CI 每次執行）

| ID | 驗證 | 方法 | 通過標準 | 狀態 |
|---|---|---|---|---|
| A1 | 申請組合 solver | 與暴力窮舉比對，隨機 80 組 m ≤ 10 的實例（同費用 + 異費用） | 誤差 < 1e-9 | ✅ `tests/test_portfolio.py` |
| A2 | 重現已發表結果 | OptimalApplication.jl README 範例的順序與期望值 | 完全一致 | ✅ |
| A3 | 推薦行為 | 金融錨點學生應看到非商學院的量化 program；錨點不重複推薦；硬限制生效 | 單元測試通過 | ✅ `tests/test_discovery.py` |
| A4 | 資料完整性 | schema 驗證、id 不重複、分數在 [0, 1] | 載入不報錯 | ✅ |

## B. 側寫品質

| ID | 驗證 | 方法 | 指標 / 門檻 |
|---|---|---|---|
| V1 | 穩定性 | 同一學生隔 1 週重測 | 各維度 test–retest 相關 ≥ 0.7 |
| V2 | 提問效率 | 模擬學生（已知真實需求向量），比較隨機 vs 自適應選題 | 達到相同 top-5 重疊率所需題數 |

## C. 探索能力

| ID | 驗證 | 方法 | 指標 |
|---|---|---|---|
| V3 | 離線回溯 | 只給學生**最初**的學校清單當錨點，看**最後實際申請 / 就讀**的 program 是否出現在 top-k | Recall@5、Recall@10（資料來源：顧問歷史案例、學長姐） |
| **V4** | **新穎且相關（核心指標）** | 學生對每個推薦標記：相關嗎？以前知道嗎？ | **相關且原本不知道的比例**；同時回報「相關比例」避免只追求新奇 |
| V5 | 與顧問比較 | 同一學生分別取得顧問清單與模型清單，匿名混合後由學生評分 | 盲評偏好率、平均相關分數 |
| V6 | 偏誤 | 推薦是否集中在熱門學校或少數 CIP | CIP 覆蓋率、推薦的學校排名分布 |

## D. 錄取模型（M4 之後）

| ID | 驗證 | 方法 | 指標 |
|---|---|---|---|
| V7 | 校準 | GradCafe 留出集 | Brier score、reliability curve；需優於「全部猜基準錄取率」 |
| V8 | 相關性影響 | 獨立 vs copula 模型 | 期望效用差、建議組合差異 |
| V9 | 穩健性 | p ±20% Monte Carlo | 最佳組合變動率 |

## 注意事項
- GradCafe 為自願填報，有選擇偏誤（錄取者較常回報）；所有 V7 結果需註明此限制。
- 使用者研究資料不進 repo；只存去識別化的彙總結果於 `results/`。
