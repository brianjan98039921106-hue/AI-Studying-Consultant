# 驗證框架 Validation Framework

## 1. 六層驗證階梯

每個部件、每個版本都要由下往上逐層通過。下層沒過，上層的結果不算數。

| 層級 | 名稱 | 回答的問題 | 方法 | 何時執行 |
|---|---|---|---|---|
| **L1** | 理論符合 | 實作是否忠於理論來源？理論的假設在我們的情境成立嗎？ | 對照 [THEORY.md](THEORY.md)，逐條列出假設並登錄到 [REGISTER.md](REGISTER.md) | 寫程式前 |
| **L2** | 驗證（verification） | 程式有沒有照規格算對？ | 單元測試、性質測試（property-based）、暴力法比對、重現已發表結果 | 每次 commit（CI） |
| **L3** | 合成還原 | 在已知真相的環境下，能不能還原真相？ | C5 模擬器：產生已知真實需求的合成學生，量測還原誤差與排序品質 | 每次部件版本更新 |
| **L4** | 盲區探針 | 已知的弱點在哪？有沒有被修好或變嚴重？ | 每個 B 項目一個探針測試；`xfail(strict=True, raises=AssertionError)` 標記尚未修復的盲區（只接受「斷言失敗」，程式錯誤不算） | 每次 commit（CI） |
| **L5** | 實證確認（validation） | 對真實學生有用嗎？ | 真實資料回溯、使用者研究、顧問盲評 | 部件達到 G2 之後 |
| **L6** | 外部審查 | 領域專家同意嗎？登錄表需要更新嗎？ | 顧問／學者審查，更新假設與盲區 | 每個大版本 |

> 為什麼要 L3 和 L5 兩層：L3 能精確量測誤差，但模擬器本身也是一組假設（盲區 S-1）；L5 是真實世界，但樣本少、沒有標準答案。兩者互補，任何一個都不能取代另一個。

## 2. 部件關卡（Gates）

| 關卡 | 條件 | 通過後可以 |
|---|---|---|
| **G0 規格** | 部件規格寫好；理論來源與假設已登錄（L1）；輸入輸出契約已定義 | 開始寫程式 |
| **G1 驗證** | L2 測試全過；部件測試覆蓋率 ≥ 90%；有參考實作可比對 | 接入 C5 模擬 |
| **G2 合成** | L3 指標達門檻；每個高風險 B 項目都有 L4 探針或書面理由 | 給真人使用（內部試用） |
| **G3 實證** | L5 指標達門檻；L6 審查完成 | 對外使用 |

## 3. 反覆驗證循環

```
規格(G0) → 實作 → L2 → L3 → L4 ─┬─ 全過 → 下一版本或下一關卡
                                 └─ 失敗 → 更新 REGISTER（新假設 / 新盲區）→ 回到規格
```

規則：
1. **每次迭代都重跑整個階梯**，不只跑改動的那層。L2 與 L4 已在 CI 自動執行。
2. **失敗必須留下紀錄**：新發現的問題一律先登錄成 B 項目，再寫成探針測試，最後才修。
3. **修好一個盲區 = 探針從 xfail 變成 pass**，並在同一個 commit 移除 `xfail` 標記、更新登錄表狀態。
4. **不允許只看一個指標**：例如新穎度提升時，一定同時回報相關度。
