# 申請結果資料：怎麼準備、怎麼檢查（C3.1）

> **⏸ 暫停（[ARCHITECTURE D13](ARCHITECTURE.md)，2026-10-29）**：錄取機率模型不在目前範圍，現在不需要準備這些資料。範本、載入器與檢查腳本保留，範圍重新納入時照本文件使用。

> 對象：要把歷年申請結果交給 C3 錄取模型的顧問。資料只放在 `data/private/`（已設定不會提交到 GitHub）。
> 模型與檢驗依據：[components/C3-feasibility.md](components/C3-feasibility.md)、[F128–F150](../results/FINDINGS.md)。目前模型**只在合成資料驗證過**，這份資料就是用來做真實檢驗（V-C3-2～4）。

## 1. 需要哪兩個檔案

| 檔案 | 範本 | 一列代表 |
|---|---|---|
| 申請結果 | [`data/templates/admission_records.csv`](../data/templates/admission_records.csv) | 一位學生對一個學程的一次申請 |
| 官方錄取率 | [`data/templates/official_rates.csv`](../data/templates/official_rates.csv) | 一個學程在一個年度的官方錄取率 |

把範本複製到 `data/private/` 再填，**不要**直接改範本。存檔用 UTF-8（Excel：另存新檔 →「CSV UTF-8」）；檔案只能有範本的欄位與 `x_` 開頭的特徵，其他欄位一律拒絕載入。欄名大小寫與前後空白不影響。

## 2. 申請結果的欄位

| 欄位 | 必填 | 內容 | 例子 |
|---|---|---|---|
| `record_id` | ✅ | 不可回推身分的代號，每列唯一 | R0001 |
| `year` | 全部填或全部不填 | **入學年度**（Fall 2025 入學填 2025；與官方錄取率檔同一定義） | 2025 |
| `program_id` | ✅ | 你自己對學程的代號；同一學程每列一致 | CMU-MSBA |
| `cip` | ✅ | 6 碼 CIP 2020 代碼；用來把學程分到族群 | 52.1301 |
| `program_type` | 全部填或全部不填 | 申請流程類型（大小寫不分） | standard／interview／portfolio／professional |
| `source` | ✅ | `complete`＝你的案例（錄取與被拒都記）；`self_report`＝網路上的自陳結果 | complete |
| `outcome` | ✅ | 最終結果；候補請等結果確定後再填 | admit／reject（也接受 1／0、錄取／未錄取） |
| `group` | 選填 | 申請者群組，用來分組檢查校準 | taiwan／international |
| `x_…` | 選填，可留白 | 數值特徵；欄名自訂，但都以 `x_` 開頭 | `x_gpa_pct`、`x_toefl`、`x_gre_q`、`x_work_years` |

**最重要的兩件事**

| 事項 | 原因 |
|---|---|
| `complete` 紀錄一定要把**被拒**也記下來 | 只記錄取會讓模型高估錄取機率（F128：高估 0.11–0.24） |
| 有多年資料就填 `year` | 預測一律針對最新年度；舊年度的整體難度會被分開估計（F148–F150） |

## 3. 官方錄取率的欄位

| 欄位 | 必填 | 內容 |
|---|---|---|
| `program_id` | ✅ | 與申請結果相同的代號 |
| `year` | ✅ | 入學年度（與申請結果同一定義）；同一學程同一年度只能有一個錄取率 |
| `admit_rate` 或 `applicants`＋`admitted` | ✅ | 錄取率（0–1 的小數，例如 0.25，不要寫 25%），或申請人數與錄取人數 |
| `source_url`、`retrieved_at` | ✅ | 出處網址與取得日期（2026-10-28 這種格式）；沒有就不能用（真實學程資料都要可查證） |

## 4. 隱私規則（載入時會自動檢查）

| 規則 | 載入器的行為 |
|---|---|
| 只能有範本欄位與 `x_` 特徵 | 其他欄位（包括「學生姓名」「Email Address」「身分證字號」等）**拒絕載入**；`x_` 欄名含姓名、電話等字樣也拒絕 |
| 儲存格不能出現 e-mail、身分證或居留證號碼、手機號碼（含空格、連字號、+886 寫法） | 偵測到就**拒絕載入**並指出列號 |
| 檔案只放 `data/private/` | 該資料夾不會被提交 |

自動檢查只能抓到常見格式（例如抓不到寫在儲存格裡的姓名），去識別化仍要你自己確認。

## 5. 執行檢查

```bash
python scripts/validate_admission_model.py \
    --records data/private/admission_records.csv \
    --rates data/private/official_rates.csv
```

| 輸出 | 意思 |
|---|---|
| 載入報告 | 筆數、完整／自陳數、特徵與缺漏數、以哪些紀錄標準化 |
| 全部資料的擬合 | 是否收斂、自陳平移、年度、官方錄取率與紀錄是否衝突（衝突時請先查資料） |
| 時間切分 | 用較早年度預測最新年度的**完整**紀錄：Brier skill（> 0 才比「只用平均錄取率」好，V-C3-2）、校準截距與斜率（理想 0 與 1）、可靠度表、各群組的 Brier（V-C3-4）。訓練只用較早年度：特徵用較早年度的平均與標準差，官方錄取率用訓練最後一年的（所以要檢查校準，最好也提供較早年度的錄取率；報告會列出兩次擬合各有幾個學程有錨點）。訓練年度沒有的族群或學程類型無法預測，會略過並計數 |

時間切分需要至少兩個年度，且最新年度至少 20 筆完整紀錄。結果寫在 `data/private/admission_check.md`（不會提交）；把摘要數字告訴我即可，不需要傳原始資料。

## 6. 載入器的處理方式（A-C3-9）

| 步驟 | 做法 | 限制 |
|---|---|---|
| 標準化 | 完整紀錄 ≥ 30 筆時用完整紀錄的平均與標準差，否則用全部紀錄 | 只用自陳紀錄時平均會偏向錄取者（報告會提醒） |
| 缺漏特徵 | 補平均，並加一個「缺漏」指標欄 | 缺漏與結果有關時只能部分處理 |
| CIP | 「9.0101」會補成「09.0101」；族群取前 4 碼 | — |
